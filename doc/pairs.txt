*pairs.nvim*  Conservative quote and bracket pairing for Neovim

Requires Neovim 0.11+. Pure Lua, no runtime dependencies.

SETUP                                                    *pairs-setup*

Disable other auto-pairs plugins, then: >lua
    require('pairs').setup({
      pairs = { ["'"] = { open = false } },
      treesitter = false,
    })
<
Handles Insert-mode (), [], {}, double and single quotes, matching closer
skipping, empty-pair <BS>, and empty-bracket expansion on <CR>.
<Tab> and other modes are not mapped.

Options:
  enabled              boolean or function(bufnr), default true
  mappings.enabled     install mappings, default true
  mappings.bs          install <BS> mapping, default true
  mappings.cr          install <CR> mapping, default true
  max_scan_bytes       maximum line prefix to scan, default 4096
  treesitter           use installed parsers for syntax context, default false
  disabled_filetypes   list of disabled filetypes
  pairs                table keyed by opening delimiter; false disables a rule
  multi_pairs          opt-in triples, templates, fences, LaTeX math; default {}
  tex_environments     TeX environment name -> text/math/literal/false
  filetypes            filetype -> rule/environment/enabled overrides

Rules contain close (single ASCII character), open, skip, delete, and newline
(booleans). Open/skip/delete default to true for new rules. Newline defaults
to true for asymmetric pairs; symmetric quotes never expand. Overrides merge
with defaults.
Closing delimiters must be unique. Multi-character rules use multi_pairs.
Single-quote opening defaults to false in text, markdown, and rust.
Re-enabling a single-character rule disabled with false requires its close value.

Buffer overrides use b:pairs_enabled and b:pairs_rules. Buffer rules override
global and filetype rules; newly introduced delimiters need explicit mappings.
Validated single/multi rule metadata from setup is reused across keys. Buffer
overrides are still read, merged and validated on every capture; changing them
does not require another setup. Filetype switches and re-setup select new rules.

PYTHON TRIPLE QUOTES                                      *pairs-triples*

Opt-in, with treesitter=true and an installed Python parser: >lua
    require('pairs').setup({
      treesitter = true,
      filetypes = {
        python = {
          multi_pairs = {
            [string.rep('"', 3)] = {},
            [string.rep("'", 3)] = {},
          },
        },
      },
    })
<
Typing the third identical quote after a complete empty short string creates
a triple pair. Python r/u/b/f/br/rb/fr/rf prefixes are supported in either case.
At its real closing delimiter each quote press skips one quote. Body quotes
pass through. <BS> removes an adjacent empty triple pair; <CR> creates a middle
and closing line aligned with the opening line. Undo/redo and dot retain the
complete insertion.

Multi rules contain open, skip, delete, and newline, all defaulting to true.
The closer must equal the opener and may be omitted. false disables a rule.
Precedence is global multi_pairs, filetype multi_pairs, b:pairs_multi_rules.
This rule family applies only to Python. Missing/pending parser context cannot
trigger triple pairing; ordinary quote handling remains the fallback.

JAVASCRIPT / TYPESCRIPT TEMPLATES                         *pairs-templates*

Opt-in for javascript/javascriptreact/typescript/typescriptreact: >lua
    local templates = {
      pairs = { ['`'] = { close = '`' } },
      multi_pairs = { ['${'] = {} },
    }
    require('pairs').setup({
      treesitter = true,
      filetypes = {
        javascript = templates,
        javascriptreact = templates,
        typescript = templates,
        typescriptreact = templates,
      },
    })
<
Install the relevant JavaScript/TypeScript/TSX parser. React filetype aliases
are handled when no custom parser-language mapping is registered.

Backticks pair, including after a tag, and skip the actual closing backtick
on the same or another line. <BS> removes an adjacent empty template, keeping
its tag. <CR> in template text remains an ordinary newline.
The outer JS/TS grammar owns template boundaries even with language injections.

In template text, { after an unescaped $ inserts {}. A following } is reused;
opening before existing words is suppressed. Inside ${...}, normal code pairing
applies. Nested templates, strings and object braces keep their own boundaries.
The actual interpolation closer is skipped; ordinary template body characters,
string/comment/regex/JSX text contexts remain protected.

<BS> in an empty ${} removes all three characters; <CR> creates an indented
middle and closing line. Backtick rules use standard open/skip/delete flags.
multi_pairs['${'] defaults to close='}', with independent open/skip/delete/
newline flags, all true. Overrides follow global/filetype/buffer precedence.
Backtick, interpolation and ordinary brace rules work independently.
Advanced template handling needs current parser context. Missing parsers use
the line-local lexer; pending parses preserve original keys.

MARKDOWN CODE FENCES                                      *pairs-fences*

Opt-in, with treesitter=true and an installed Markdown parser: >lua
    require('pairs').setup({
      treesitter = true,
      filetypes = {
        markdown = { multi_pairs = { ['```'] = {}, ['~~~'] = {} } },
      },
    })
<
At the end of a new opening line with three or more backticks/tildes and an
optional language/info string, <CR> adds a middle and closing line. The cursor remains
on the middle line. The info string is retained; both lines use the opening
line's indentation, which may contain zero to three spaces relative to a
containing list/quote. The generated closer matches the opening character and
exact length.

Existing body content or a closing fence inserts one line, preserving the
block. Within a container, that line receives the continuation prefix.
At a confirmed closing delimiter, each delimiter character skips one position.
An existing closer must use the same character and be at least as long as its
opener. Shorter/different-character lines remain body content.
The outer Markdown tree owns these boundaries even when the body has an
injected code-language parser.

Backtick and tilde openers work at the top level, in lists/block quotes and in
nested combinations. List markers become continuation indentation; quote
markers remain. For example, Enter after '> - ```lua' creates: >
    > - ```lua
    >   |
    >   ```
<
The | represents the cursor. Prefix tabs become spaces at Markdown's four-column
tab stops, independently of buffer tabstop/expandtab. Native comment leaders
and indentexpr do not duplicate or change the generated prefix.

Inline code, HTML, indented code relative to its container and task-marker text
retain ordinary input. Inline backtick pairing is not
enabled. Enter inside the info string or existing body stays native. See
CommonMark 4.5, 5.1 and 5.2 for the syntax contract.
Backtick-fence info may not contain backticks; tilde-fence info may contain them.

multi_pairs['```'] and multi_pairs['~~~'] configure independent families for
all opening lengths >= 3. Longer configuration keys are rejected. close defaults
to the family key; generated closing text matches the actual opening length.
open/newline/skip default to true. Expansion requires both open and newline.
false disables that family. Overrides follow global,
filetype, then b:pairs_multi_rules. Backspace stays ordinary; delete=true is
unsupported and rejected. Undo/redo and dot retain the complete insertion.
Missing/pending parser context preserves original keys.

For a completion-owned Enter, use the usual accept -> expr('<CR>') -> fallback
chain. Language completion is accepted first; a subsequent Enter expands.

LATEX DISPLAY DOLLARS                                    *pairs-tex*

Enable with treesitter=true and an installed latex parser: >lua
    require('pairs').setup({
      treesitter = true,
      filetypes = {
        tex = { multi_pairs = { ['$$'] = {} } },
        plaintex = { multi_pairs = { ['$$'] = {} } },
      },
    })
<
The first $ stays literal. The second upgrades $| to $$|$$ only when that
line contains indentation and one dollar, with whitespace or nothing after
the cursor. | denotes the insertion cursor. tex/plaintex use the latex alias
unless an explicit language registration overrides it.

Parser-confirmed closing $$ skips one dollar at a time. <BS> deletes an
adjacent empty $$ pair. <CR> expands it into three lines; the body and closer
use the opening indentation, including tabs. Nonempty displays keep native
Enter. Body dollars and mismatched closers stay literal. Inline single-dollar
math and backslash parentheses/brackets are outside this rule.

Comments, existing math and verbatim/listing/minted environments stay literal.
Inline \verb spans (including unfinished spans) are protected. \lstinline and
\mintinline conservatively protect their remaining line. Opening recovery in
unfinished document/center/list/figure and other known text environments is
bounded to 256 syntax nodes. Unknown environments, unresolved earlier
delimiters and missing/pending parser context keep original input. No full
synchronous parse or buffer-wide text scan is requested.

close defaults to '$$'. open/skip/delete/newline default to true and are
independent. false disables the rule. Overrides follow global multi_pairs,
filetype, then b:pairs_multi_rules. Native undo/redo/dot are preserved. For a
completion-owned Enter, use accept -> expr('<CR>') -> fallback as usual.

LATEX BACKSLASH MATH                                     *pairs-tex-slash*

Enable inline and display math independently, with the latex parser: >lua
    require('pairs').setup({
      treesitter = true,
      filetypes = {
        tex = { multi_pairs = { ['\\('] = {}, ['\\['] = {} } },
        plaintex = { multi_pairs = { ['\\('] = {}, ['\\['] = {} } },
      },
    })
<
Typing \( produces \(|\); typing \[ produces \[|\]. | denotes the insertion
cursor. The backslash prefix must be unescaped and parser-confirmed text;
existing math/comments/literal code, unknown environments and unsafe incomplete
syntax preserve input. The next character must permit pairing. Opening can
follow ordinary text; it does not require a standalone display line.

Typing \) or \] at a confirmed closer skips both existing characters one at a
time, including the backslash. A bare ) or ] before the whole closer remains
literal. <BS> removes an adjacent empty pair. <CR> in \[|\] creates three lines
with opening indentation on the body and closer. Inline/nonempty formula Enter
stays native by default. Undo/redo/dot retain the full insertion.

close defaults to '\\)' or '\\]'. open/skip/delete default to true. newline is
false for '\\(' and true for '\\[' and can be overridden independently.
false disables either rule. Precedence and missing/pending parser fallback are
unchanged. Ordinary brackets and backslash commands keep their usual behavior.

Either rule installs a deferred Insert backslash mapping in addition to the
bracket keys. Existing mappings are preserved and reported in status().conflicts;
custom owners can compose expr('\\') to skip the backslash of a proven closer.
Completion/snippet edits are not re-paired. For completion-owned Enter, use
accept -> expr('<CR>') -> fallback as usual.

LATEX ENVIRONMENT DECLARATIONS                           *pairs-tex-env*

tex_environments extends known modes in tex/plaintex. Requires current latex
parser context; declarations do not enable math delimiter rules themselves: >lua
    require('pairs').setup({
      treesitter = true,
      tex_environments = {
        abstract = 'text', theorem = 'text', proof = 'text',
        mymath = 'math', mycode = 'literal',
      },
      multi_pairs = { ['$$'] = {}, ['\\('] = {}, ['\\['] = {} },
    })
<
text       Allow configured math pairs at proven boundaries.
math       Keep math delimiter input literal; ordinary brackets still pair.
literal    Keep all pairing keys native, including quote/bracket input, BS, CR.
false      Remove a text/custom declaration; treat the name as unknown.

Defaults include document/list/figure/etc. text environments and the parser's
built-in math/raw environments. Built-in protection cannot be weakened/removed;
math can be strengthened to literal. Parser-confirmed math/comments/raw nodes
remain protected. Names match exactly, including star suffixes (no wildcards).
Names are 1-62 ASCII letters/digits or _, ., :, -, * characters.

Precedence: defaults -> global tex_environments ->
filetypes[ft].tex_environments -> b:pairs_tex_environments. For example: >lua
    vim.b.pairs_tex_environments = { proof = 'text', mycode = 'literal' }
<
Inner text cannot lift outer math/literal restrictions. Raw code ignores other
environment-looking text until its own matching end. Closed sibling scopes do
not leak. Complete begin headers establish modes before an end is written,
including trailing blank lines; partial headers remain conservative. Each
prefix traversal visits at most 256 syntax nodes and excludes future content.
Custom raw modes inspect preceding scope metadata; unresolved/over-budget
prefixes keep all pairing keys native. No full buffer-text scan or synchronous
parse is requested. Mismatched/unprovable scopes preserve input.

VimTeX indentation, mapping ownership and completion/snippet expansion remain
independent. Missing parsers use the existing line-local lexer fallback;
environment modes require parser evidence. Pending parses pass keys through.
Invalid setup options preserve existing setup; invalid buffer declarations
pass through with explain().reason='context_error'.

LATEX COMMAND ARGUMENTS                                  *pairs-tex-args*

With treesitter=true and a current latex parser, built-in command parameters
have their own context in tex/plaintex. No new setup option is needed: >lua
    require('pairs').setup({
      treesitter = true,
      multi_pairs = { ['\\('] = {} },
    })
<
Text: section/subsection/subsubsection/chapter/part/paragraph/subparagraph
(including starred forms and optional titles), textbf/textit/textrm/textsf/
texttt/textnormal/emph/underline. Ordinary brackets and configured \( ... \)
pairs work inside their text arguments; display openings \[ and $$ stay native.

Raw: url/nolinkurl/path payloads and href's first mandatory argument preserve
quote/bracket/math input, BS and CR. href's second mandatory argument is text;
its optional settings stay conservative for math. Payload %20 and quotes do not
poison following text after the argument ends; a real following comment remains
protected. Escaped braces and nested groups are accounted for.

Outer argument braces and heading optional-title brackets follow normal rule
options. Proven structural closers can be skipped, even across lines. BS between
empty outer delimiters can delete both. Interior raw brackets remain native.
Typing \( at \textbf{|} yields \textbf{\(|\)}; typing ( at \url{|} yields
\url{(|}. Here | marks the insertion point, not a literal character.

Incomplete parameters and trailing blank lines use current syntax anchors and
a prefix of at most 32 lines/4096 bytes. The byte budget is checked before
reading; future body text and full buffer scans are not requested. Unsafe or
over-budget recovery preserves input. Unknown command parameters remain
conservative for math. Outer math/raw environments, comments and text-in-math
nodes keep their restrictions. Missing parsers use the line-local fallback;
pending parses pass through without forcing synchronous parsing. With
treesitter enabled, LaTeX lines beyond max_scan_bytes also pass through so a
long future suffix cannot bypass raw protection.

VimTeX indentation, completion/snippets and mapping ownership keep their own
behavior. Built-in profiles above are fixed, not a configurable command API.

ENTER                                                    *pairs-enter*

<CR> between adjacent empty brackets creates an indented middle line and a
closing line. Strings, comments, quotes and nonempty pairs pass through.
Indentation uses indentexpr or cindent when configured. Otherwise it adds one
shiftwidth to the opening line and aligns the closer with that line. Tabs and
vartabstop are respected. Undo, redo and dot repeat retain the entire insertion;
dot replays the resulting indentation from the original insertion.

Existing Enter mappings are preserved. For a completion-owned Enter, set
mappings.cr=false and compose expr('<CR>') after completion confirmation and
before the owner's native fallback. See the blink.cmp example in README.md.

API                                                      *pairs-api*

setup(opts)            Validate config and install non-conflicting mappings.
expr(key)              Return handled keycodes, or nil for caller fallback.
handle(key)            Return handled or original keycodes.
explain(key, opts)     Return action/reason without editing; Insert mode by
                      default. opts.assume_insert previews insertion before
                      the Normal-mode cursor.
enable([bufnr])        Enable globally, or enable one buffer.
disable([bufnr])       Disable globally, or disable one buffer.
toggle([bufnr])        Toggle globally, or toggle one buffer.
status()              Initialization, global enabled state, mapping conflicts.
teardown()            Remove only mappings still owned by this plugin.

Use key notation such as '<BS>' or '<CR>'. expr()/handle() return termcodes; mappings
should use { expr = true, replace_keycodes = false }.
Plugin-owned mappings use <Ignore> before a private expression mapping to flush
preceding typed text. Composed mappings should consider |map-expression| order.

COMMANDS                                                 *pairs-commands*

:PairsToggle           Toggle pairing globally.
:PairsInspect {key}    Preview insertion before the cursor; does not edit text.
:checkhealth pairs     Inspect initialization and setup-time mapping conflicts.

BENCHMARK                                                *pairs-bench*

From the plugin checkout: >sh
    ./tests/bench.sh
    PAIRS_TEST_PARSER_ROOT=/tmp/pairs-parsers \
      PAIRS_BENCH_OUTPUT=/tmp/pairs-benchmark.json ./tests/bench.sh
<
Use tests/install-parsers.sh to prepare the optional pinned parser fixtures.
The benchmark runs in isolated XDG directories and reports decision timing
in microseconds (median/P95/max), plus separate mapped input batch timing.
Mapped batches check resulting text, undo/redo and dot repeat.

PAIRS_BENCH_SAMPLES defaults to 1000 (minimum 100), PAIRS_BENCH_LINES to 50000
(minimum 1000), and PAIRS_BENCH_MAPPED_SAMPLES to 20 (minimum 5).
PAIRS_BENCH_PROFILE=1 adds an instrumented stage breakdown outside the latency
measurements. JSON includes source/benchmark fingerprints and environment data.
The separate GC-paused Lua heap estimate measures allocation growth, not
retained memory. Screen rendering and physical keyboard latency are excluded.
CI checks behavior without timing thresholds. See docs/BENCHMARKS.md for methods
and a measured before/after comparison.

LIMITS                                                   *pairs-limits*

The fallback lexer is line-local. It recognizes common line comments and basic
quoted strings, not complete language grammars. Escaping uses backslash parity;
non-ASCII neighbors conservatively block quote opening. Malformed bracket
prefixes and scans exceeding max_scan_bytes pass through.

treesitter=true protects raw/multiline strings and block comments. Python
f-string expressions and JavaScript/TypeScript template substitutions are code;
format/literal text stays protected. Completed string/comment nodes are masked
in the current line prefix before the lexer checks nesting.

Stale/unparsed trees are refreshed using Neovim's time-sliced parse callback
API. No full synchronous parse or wait is requested. Pending trees and unsafe
incomplete literals pass keys through. Missing parsers use the line-local lexer.
Current-line traversal is bounded to 256 nodes (syntax_limit on overflow).
This option does not install parsers or start highlighting. See README.md for
pinned parser fixtures used by the regression suite.

Existing global mappings are preserved; buffer mappings take precedence.
Paste, macro recording/replay, Replace mode, and special buffers bypass pairing.
Runtime context errors pass through and are exposed by explain().

Other multi-character pairs, wrapping and command-line mode are planned.
See README.md and docs/PLAN.md in the checkout for details.
